Gateway usage: the changes to make

Implementation handoff. Baseline measured on the live board, 2026-11-02 17:29–17:48 EST, on wtgui/research-whether-our-her-f16888 at 9d4e9b8 (Hermes 0.22.5). The full measurements are in docs/gateway-usage-review.html on the same branch. Written for the agent that will implement this: every change names its file:line, the number that should move, and the test that proves it.

The constraint that shapes everything below

Every turn must be able to handle an event from an agent this assistant manages. There is no rate cap on events. The original recommendation — "cap wakes at 10/hour" — is withdrawn: at 10/hour the assistant answers at most once every six minutes, which is the failure the reader objected to. The evidence says the cap is already dropping real events today: seven watch finished wakes were refused by the budget between 22:32 and 22:54 (journal wake-suppressed, "rate limit reached (6/h)"), because Assistant #2 runs on the default 6/hour and only settle and exited are exempt.

So the three changes are: (1) make the wake budget cover only the sentry's speculative sweeps, never an event; (2) stop re-sending the unchanged charter on every turn; (3) put the board digest on a wake counter for sweeps — an event turn always sees the board. With the charter and digest gone from the hot path there is room to wake twice as often as today and still send fewer bytes (§5).

2. Change 1 — event wakes are never budgeted

What it does. Split the 17 rules into two classes. A sweep is a condition the 5 s sentry polls: quiet, loop, errorloop, leftover, repeat, child, noevidence, context, collision, spawnidle, spawnlost. Everything else is an event: something happened to a run the assistant manages (approval, question, settle, exited, watch, interrupted) or the reader/restart asked for a turn (complete, resume, restart, or no rule at all). The hourly budget applies to sweeps only; an event is never refused. The list is written as the sweeps on purpose: a rule added later defaults to event, so it cannot silently become droppable.

Why this is safe from a storm. Four guards already exist and stay: wakes coalesce for 150 ms (lib/assistant.js:2826-2829), one terminal wake per finished run (:1728, terminalClaim), a rule does not re-fire for the same subject inside rearmSeconds (default 900 s, :1694), and one assistant cannot have two live turns at once (assistantLive, :2764/:2848). A hundred settles in one pass are still one turn.

3. Change 2 — the board digest on a sweep counter

What it does. The board digest (7,975 B) is rebuilt every turn and mostly restates runs that have not moved. Give it the same knob the queue digest already has: digestSweepEveryNWakes. A sweep carries it one wake in N; an event turn and a reader's own message always carry it. This is why Change 1 goes first: the gate needs to know which kind of wake it is.

4. Change 3 — the charter sent when it changes

What it does. The charter is 19,720 B — 53% of every turn — and it is the same text turn after turn. Send it in full on the first turn of a thread, whenever the file's sha changes, and every charterRefreshTurns turns (default 20) as a compaction safety net; on every other turn send a one-line marker that names the sha and says the long tier is still in force.

Why the refresh exists. The gateway compacts long threads: panel-assistant holds 9,080 messages, of which only 117 are active, with 8,341 compacted. A compaction is a summary, and a summary can drop charter detail. Re-sending every 20 turns bounds that exposure to at most 20 turns, and costs 986 B/turn amortised. The memo lives in memory, so a panel restart re-sends on the first turn for free.

5. What the three changes add up to

At the measured 43 turns/hour, with the digest on every turn and the charter amortised. The last three rows are the point: twice as often as today (86 turns) still sends 13% fewer bytes; three times as often costs 31% more, and buys three times the responsiveness. The per-turn payload falls by more than half either way.

Bytes/turn after = 9,279 (everything but charter and digest) + 7,975 (digest) + 986 (charter amortised over 20 turns). Gated sweep turns average 5,317 for the digest, which is the "half gated sweeps" row. The baseline row is the measured 1,794,889 chars from db-inputs.js; the others are arithmetic on that baseline.

The exchange rate. Today's budget has to choose between answering events and saving bytes — that is why seven watches were dropped. After these changes an event turn costs 17,254 B instead of 36,974 B, so the panel can answer 2.3× as many events for the same bytes, or 2× the events at 13% fewer bytes. Responsiveness stops being the thing that gets traded away.

6. Order, tests, rollback

  1. Change 1 first (event/sweep classes). It is the correctness fix and Change 2 depends on the event flag it computes in flushWake. Ship it alone if the rest slips: it stops the budget from dropping events.
  2. Change 2 (digest) second: smallest diff, and the knob is a copy of an existing one.
  3. Change 3 (charter) last: it changes what a turn is told, so it wants a live read of a few turns before it is trusted.

Tests. node --test test/assistant-event-wakes.test.js (new), node --test test/assistant-profile.test.js test/assistant-queue-directive.test.js test/roles.test.js test/assistant-settings-split.test.js (existing callers of preamble()), then npm test (node --test --test-concurrency=4 test/*.test.js).

Rollback. Change 2 is a knob: digestSweepEveryNWakes: 1 restores the digest every wake. Change 3 is a knob: charterRefreshTurns: 1 restores the charter every turn (a setting, no code). Change 1 has no knob by design; reverting it is the two-line budget check. No state migration: this.wakes becomes the sweep ledger, and its meaning is only displayed.

8. Handoff checklist

  • Read the constraint at the top. No change may gate an event wake.
  • Change 1: SWEEP_WAKE_RULES, the budget check at lib/assistant.js:2817, the ledger at :2852, the event flag on the wake origin, the state rename and the Settings label.
  • Change 2: digestSweepEveryNWakes (default 1), digestForTurn(), the preamble block at :2713, the flag through :2775 and :2862.
  • Change 3: charterBriefing(id, { turn }), the memo in the constructor, createHash, the turn through say().
  • Update the four existing tests that call preamble() without { turn: 0 }.
  • Run npm test and paste the pass/fail line into the PR.
  • After deploy, run node db-inputs.js and the wake-suppressed query above; the first should show ~17 KB per turn, the second no event rule.
  • Report the wake count for the first hour. If it is far above 43, say so — that is the design working (events are being answered), not a regression, and §5 says what it costs.
