The answer

Four defects, four changes, no new state. A stage's declared artifact now decides whether its worker is told to push: a document stage commits on its branch and reports the commit, a pr stage still pushes and opens one. A run's own end asks the pipeline sweep for the advance instead of leaving it to the minute ticker. An unattended stage worker is told which tools work and which one the platform refuses. And the ping-pong's verdict gate declares its record, so an accepted draft ends the loop instead of entering another visit and running to the cap.

All four are driven by the panel's own clock in the tests: the sweep for the start spec, the real spawner and a spy gateway for the run body, the hold's sweep for the settle, and the seed's ping-pong for the loop.

1. A stage's landing is its artifact's

The defect. lib/assistant.js startSpawn passed no remote-write flag and lib/branch-policy.js rendered the PARENT's paragraph, so a stage writing ledger/ping-pong/draft.md was told to push its branch and open a pull request — and did (PR #607).

The change. The driver reads the stage's one declared word and carries it on the start: remoteWrite: "pr" for a stage whose artifact kind is pr, "local" for every other kind. It rides the spec through startSpawn and the real spawner into lib/jobs.js, which renders the LANDING paragraph's third case — commit on the stage branch, report the commit, no push, no PR — without asking for the parent at all. A pr stage and an ordinary (non-pipeline) worker take the paragraph they always did.

The seed follows the rule. The landing ladders declare kind: "pr" on the stages that act on the remote (turnover.push/.pr; github-force-merge's push, pr, merge and main; sefl-review-loop's push, pr, address and merge) and nothing on their commit stages, which are local commits. A push stage told "do not push" is a pipeline that cannot do its job; a read-only stage of the review loop stays local and loses nothing.

The tests. test/spawn-stage-landing.test.js is the acceptance test: it runs the seed's ping-pong stage prompt through the real spawner, the real job store and a spy gateway, and asserts the run body the gateway received — local-only, "commit on the branch and report the commit", gh pr create absent — then asserts a pr stage and an ordinary worker still get push and PR. test/branch-policy.test.js renders both paragraphs for the same tree cut from main; test/task-pipeline-sweep.test.js pins the driver's two words on two real starts.

For round 7: both ping-pong stages declare a document, so both starts carry local, no branch is pushed and no PR is opened by either. The critic's gh pr create from round 6 has nothing to meet.

2. The settle is the run's own end

The defect. The drafter's job ended at 22:58:31.719Z and the stage settled at 22:59:23.923Z — 52.2 s of a nine-minute stage, and most of a short one. The hold was stamped at the settle and then waited for the panel's 60-second ticker, which was its only owner.

The change. Jobs takes an onStageSettled hook. Stamping a hold now fires it, deferred one event-loop turn so the advance never runs inside the run's own settle, and server.js wires it to one tickPipelineWaits(). The ticker stays for a hold whose run the store never saw end (a restart, a dropped stream): both doors meet the same compare-and-set, and the advance itself is idempotent.

The test. test/pipeline-wait.test.js, "a run's end asks the sweep AT ONCE": a hold on a done card is stamped, the hook is shown to be deferred, then to have asked the sweep once with the settle's own instant, and the row is advanced by that sweep — no clock, no minute.

3. The unattended toolset says what it is

The defect. The critic's first call was execute_code, answered BLOCKED: this session runs on an unattended platform (api_server) with no user present. It cost a turn before the fallback to terminal.

The change. stagePrompt now ends with a TOOLS line naming the tools an unattended run can use — terminal, read_file, write_file, patch — and the one the platform refuses, with the sentence it answers. Every stage start is such a run, so every stage carries it.

The test. test/task-pipeline-drive.test.js, "stagePrompt names the tools an unattended stage may use, and the one the platform refuses": the refused tool and the working one are both named, once.

4. How the loop ends: the verdict, not the cap

The defect. ping-pong.gates[0] carried decision: null, so gateAfter answered nothing and the back edge H-02 was taken in kind order whatever the critic wrote. An accepted draft still entered another visit; a converged round ran to the cap and parked for a person.

The change. The gate declares its record — ledger/ping-pong/verdict-r{{round}}.json, outcomes accept and revise, routed accept → null (the pipeline ends here) and revise → H-02 — one file per round, so a stale verdict cannot answer the next one. And because the panel never writes a decision, stagePrompt now adds a GATE block to the stage that owns the record: where it goes, the words it may hold, and where the document routes each — with the round filled the way the driver fills it.

The tests. test/task-pipeline-verdict.test.js walks the shipped ping-pong through the panel's clock twice: an accepted draft finishes the row at visit 1 with no crossing charged, and a revised one crosses H-02 once, enters draft visit 2, and the second round's accept ends it with crossings to spare. Both fail against the old decision: null (checked by reverting the gate and re-running). test/pipeline-bundle-seed.test.js pins the gate's outcomes, routes and per-round path; test/task-pipeline-drive.test.js pins the prompt block.

What this does not prove

  • The next round is the proof of the first fix. The tests assert the run body the gateway was asked to start; whether round 7's seat obeys it — and opens no PR from either stage — is the run's own fact, not this page's.
  • The settle figure is a mechanism, not a benchmark. The hook removes the ticker from the path; how fast the advance lands also depends on the store and the spawner on the day.
  • G1's accept route is only as good as the critic's file. A critic that ends its turn without writing verdict-r{{round}}.json parks the row on pipeline-gate — by design, and named in its prompt — rather than guessing a verdict.
  • The seed's landing ladders are data, not exercised here. Their kind: "pr" is pinned by pipeline-bundle-seed.test.js; no test walks a real turnover row end to end.
