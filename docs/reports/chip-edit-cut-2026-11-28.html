How the gate was run, and the one harness patch

Run as shipped, the same gate answers 99 pass and 26 fail on the merged head, and 98 pass and 27 fail against the pre-cut module (the 27th being the script-order inspection, which a tree without chip-edit.js cannot pass). The cause of the 26 is the sandbox, not the module: with no worktree row on the board, the card's host container is display:none, so box.focus() is a no-op, document.activeElement stays on <body>, and every keystroke lands nowhere while paste events, dispatched at the element, still work. The run quoted above reveals the hidden chain inside the probe's focusBox before focusing, and changes nothing else:

probe.focusBox = (sel) => {
  const box = document.querySelector(sel);
  if (box) {
    for (let n = box; n && n !== document.documentElement; n = n.parentElement) {
      if (getComputedStyle(n).display === "none") n.style.display = "block";
    }
    box.focus();
  }
  return Boolean(box);
};

With the patch, 24 of the 26 keyboard-dependent reds go green and the same two (i) reds remain. Both counts are quoted so the reader can see the patch's whole effect: 99 to 123 pass, 26 to 2 fail.
