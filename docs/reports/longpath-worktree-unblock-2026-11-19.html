6. The disappearance of the push-local tree: attribution

That tree and its branch were present in a worktree list read partway through this run and absent from the next read. The commands this run executed are worktree add, worktree remove, worktree prune, config and branch -D on the orphan only. git worktree prune and git worktree remove delete directories and administrative entries; neither deletes a ref. A missing local branch therefore cannot come from this run's command set.

The panel's own release path does exactly the observed pair, remove followed by branch delete, in this order:

LocationWhat it does
lib/assistant.js:2150git worktree remove --force <treePath>
lib/assistant.js:2157git branch -D <branch> immediately after the remove
lib/worktrees.js:848git branch -D <branch> in the normalised tree remover
lib/steward.js:454git branch -D <branch> in the steward cleanup

Three readings support a concurrent panel release rather than this run: the branch is gone locally and still present on origin at 35bb319; the tree's admin directory in .git/worktrees is gone while its directory also is; and the repository shows other panel activity the same hour (the fast-forward tree's admin entry and the main ref were both rewritten at 13:37, before this run's first read). The branch is recoverable, with no data loss, because its tip de272dd is still referenced by two surviving branches: 

git -C C:/ProjectDevelopment/sales-territory-poc branch 20261112_1852_ROPER_pushMainToOriginOverSsh de272dd

This run did not run that command. Recreating the branch, or the tree, would undo a release the panel chose to make, so the decision is left to the reader; nothing is lost either way.

7. Root cause, and the safe tree-name length

The longest path in this tree is a tracked source file, not build output: sales-territory-POC-stage-4/sales-territory-web/src/test/resources/canary/openapi-contract/sales-territory-service/src/main/java/com/sefl/canary/service/AccountsResource.java is 174 characters on its own, and 275 once it sits under the 46-character tree name the panel chose. The 374 committed .class files under bin/ are the paths git named first in the failure, but the longest of them is 266 characters, so untracking bin/ would not remove the blocker: the src/test/resources path would still be 275.

The arithmetic is therefore fixed at 229 characters plus the length of the tree directory name (measured: 245 at a 16-character name, 275 at 46). On Windows with core.longpaths unset and HKLM LongPathsEnabled at 0x0, that puts the safe limit on a tree directory name at 30 characters:

The applied setting is the only option that unblocks the cut at an arbitrary tree name without an administrator change. The name-length limit is the one to carry into the panel: a 30-character cap prevents this on any host, in any tool, with no configuration at all.
