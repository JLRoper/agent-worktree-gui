1.153.0 - the four ways a member closes, the two facts behind them, and what each unreadable read answers.

The exit gate no longer believes a status word. It reads the pull request through the host's API and the member's content on origin/main, and it answers met, not met, abandoned or cannot tell. Cannot tell blocks.

Why content, and not ancestry

This repo lands by squash, which rewrites the sha. A landed member's commit is not an ancestor of main and never will be, so merge-base --is-ancestor would refuse exactly the members that did land. The landing read resolves the recorded sha and the main ref, takes the merge base, lists the files the change touched, and diffs only those files between the sha and main. Equal content is the landing. Ancestry is recorded on the answer (ancestor: false for a squash) and is never the verdict lib/wave-evidence.js:132-163.

The proof is a real repository, built by the test, not a stub:

test("a squash-merged member still closes: the sha is not an ancestor, and the gate judged CONTENT")

The state is still derived on every read

No state, doneAt, abandonedAt or percentage is written to waves.json. The fold runs on every GET /api/waves and on every GET /api/initiatives, from the same members and the same evidence map, so the lane and the route cannot disagree routes/waves.js:117-138, routes/initiatives.js view(). The only memo is a 30 s cache of EVIDENCE per member, keyed by PR number and recorded sha, never of a state word server.js:1855-1920. A task whose number or sha changes misses the memo at once.

The abandonment is a sentence, not a fifth state

The queue's four states stay the queue's lib/assistant/queue.js TASK_STATES. A person abandons a member with a reason, recorded through the edit door (editTask, lib/assistant/queue.js:951); the wave fold draws the member as abandoned in place of the stale state word and closes the gate as abandoned, naming the member and the reason lib/waves.js:547-560, public/core/waves-lane.js memberHtml. An unnamed abandonment is refused: it cannot close a gate, and it cannot dodge a running member.
