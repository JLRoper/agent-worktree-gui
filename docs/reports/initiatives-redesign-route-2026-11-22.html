This page is a rebuild. The first one was lost.

The original implementation report was written by row 205's worker into docs/reports/initiatives-redesign-route-2026-11-22.html as an untracked file in its worktree. When the worktree went away the file went with it, and it never entered the landing: git diff c2692598 ddea5f49 -- docs/reports prints nothing, which is the whole diagnosis. That is why the redesign shipped with its captures on main and no page that paired them with its deltas.

There is a second half to the cause, and it is the one that made the loss silent: this clone's .git/info/exclude carries docs/reports/*.html under the comment "Generated reports are local artefacts", and info/exclude is shared by every worktree. git check-ignore -v names the line. A report written under docs/reports/ therefore does not appear in git status at all, so "untracked" here does not mean "visible and forgotten" - it means invisible, and a worker who checks git status before committing sees a clean tree and believes it. Every .html report that is on main got there through git add -f; this one does too.

What changed in this rebuild, said plainly:

  • It is written to the tree and committed before the push, which is the fix for the cause, not a different cause.
  • Every number is re-measured at the current head with a named probe, or marked quoted from PR 852. The before column is re-measured too, from a git archive of 86bea38 (1.157.1) served by the same harness, so both columns are the same day's reads rather than one old ledger and one new one.
  • Where PR 852's prose and its own measurement ledger disagree, both are shown and the one that is trusted is named. Four such places are recorded in section 5; none is smoothed over.
  • The 25 PNG captures under docs/assets/initiatives-redesign/route/ are inlined here unchanged. The brief that ordered this rebuild said "28 captures"; the directory holds 28 files, of which 25 are images and 3 are the two capture ledgers and the harness. All 25 images are on this page; the ledgers are linked.

2How to read a number here

Three marks, and nothing on this page carries a number without one.

re-measured
Read out of the painted page at ef14eea (1.157.4) by the probe named in the row, after the landing. The before column comes from the same probe run against a git archive of 86bea38 (1.157.1), unpacked outside the repo: the harness is this tree's, only the product it serves moves, which is what makes a row a comparison of the tab rather than of the measurement.
quoted
From PR 852's own body, or from the committed ledger beside the captures. Reproduced because the landing said it, not because this run re-derived it. Where the ledger and the prose disagree, both are printed.
derived
Arithmetic on two numbers that are themselves measured, or a contrast ratio computed from the two hexes named in the source. The row says which.

The probe is one script, run twice, with the same page function as the landed harness. It measures the folded row's height, the open plate's height, the pane's width and scroll height, the computed type step of every run of text, the contrast ratio of each ink composited through every translucent layer above its ground (so a chip on a card is measured against the card), and it looks for all 78 strings the API document holds in the rendered tab with every fold open. Nothing it reports is read out of the source; the source is only read afterward, to explain what it found.

The measurement function, as the probe runs it (folded rows, plate, pane, contrast) 
const pane = document.getElementById("as-initiatives");
const foldedRows = [...document.querySelectorAll("#as-initiatives .init-card.is-titlecard")];
const openCard = document.querySelector("#as-initiatives .init-card:not(.is-titlecard)");
// contrast: the text colour over the first opaque stack of ancestor backgrounds
// (rgba composited down to the ground the pane is painted on), WCAG 2.x relative luminance
return {
  pane:   { width: Math.round(pane.getBoundingClientRect().width),
            scroll: Math.round(pane.scrollHeight) },
  folded: foldedRows[0] ? Math.round(foldedRows[0].getBoundingClientRect().height) : null,
  foldedRowHeights: foldedRows.map((el) => Math.round(el.getBoundingClientRect().height)),
  openCard: openCard ? Math.round(openCard.getBoundingClientRect().height) : null,
  contrast: { desc: contrast("#as-initiatives .init-desc"), ... },
};

5Where the record disagrees with itself

These are the places a reader could take a wrong number from the landing. None is reconciled silently: both readings are printed, and the one this report trusts is named with its reason.

1. "+263 at 347" is the pane's scroll delta, not the plate's. The plate grows 268.

PR 852 says: "The opened plate is 1164px against 931px at 480 (+233), pane scroll +170; at 347 the pane grows +263." The ledger at 347 reads the plate as 1429 against 1161 - a delta of +268 - and the pane's scroll as 2209 against 1946 - a delta of +263. The sentence pairs a plate delta at one width with a scroll delta at the other, and calls both "the opened plate".

Trusted: the ledger rows, which are re-measured here twice over (this run and the landing's own). Plate at 347: 1161 -> 1429, +268. Pane scroll at 347: 1946 -> 2209, +263. At 480: plate 931 -> 1164, +233; scroll 1660 -> 1830, +170. Four numbers, four different quantities; two of them were in the PR's sentence and one was wearing the other's label.

2. "mean row 145px vs 166px" - 145 and 166 are the first rows. The means are 142.7 and 150.7.

The ledger's three folded rows at 1440 docked are 166 / 133 / 153 before and 145 / 142 / 141 after. Their means are 150.7 and 142.7; the spread collapses from 33 to 4, which is the claim the sentence is really making and which the ledger does support. 145 and 166 are the first row of each set, not the mean of it.

And the flattening is a 1440-docked result. At 347 the first row is 166 in both, and the mean rises from 150.7 to 156.7, spread 33 -> 24. At the wide float it falls from 146.3 to 141.7, spread 20 -> 1.

Trusted: the per-row arrays, which are raw reads. The sentence's "flatter" is true at 1440 docked and at the wide plate, false at 347, and the redesign did not claim otherwise anywhere else.

3. 4.9:1 and the token comment's 5.0:1 are the same ink on two different grounds.

The token block annotates --tab-ink-3: #7f8a9a as 5.0:1 on --tab-surface (#141922), and the flat pair does compute to 5.04:1. The probe reads 4.9:1 because the description's first instance in the pane is the folded preview, which sits on the pane's own ground #171c24, not on a plate; #7f8a9a on #171c24 is 4.89:1. The before ink #9aa4b2 reads 6.78:1 on that same ground, which is the 6.7 in the PR.

Trusted: the probe for the folded preview (4.9 / 6.7, which is the comparison the PR makes and the state a reader meets first), and the flat pair for the plate (5.04 / 6.99). Neither is a regression of the other; a reader who quotes 5.0 for the folded row would be quoting the wrong background, and one who quotes 4.9 for the plate would be doing the same in reverse.

4. "28 captures" is 28 files: 25 images, two ledgers and the harness.

The directory holds 28 entries. 25 of them are PNGs: 12 before, 13 after. The other three are captures-before.json, captures-after.json and capture-route.mjs. This page inlines all 25 images and links the other three.

Trusted: the directory listing, which is the only reading that survives a reader opening the folder and counting.

6What the tab does now, surface by surface

The numbers above measure a design; this is what the design is, in the order a reader meets it.

The folded ledger is a ledger

Four initiatives, one ground, a hairline between rows. Each row carries a 27px route gutter with one dot per wave in that wave's own state, the title at 15.5px, a two-line preview at the third ink, and the counts with the status word at their end. A row that has no waves says no waves; a row whose wave store cannot be read says waves unreadable rather than drawing an empty route. That is routeGlyph at public/core/initiative-fold.js:288, drawn at public/assistant.js:3864, styled at public/style.css:5062 and :5133. The row heights at 1440 docked are 145, 142 and 141: the spread is 4px where it was 33.

The plate is a plate

Opening a row lifts it onto a surface with one radius and one elevation. Inside: the numbered station route, the description at the body step, the Projects column, the tier sentence that says who may change the map, and the wave block. The preamble that used to sit above all of this is behind About, word for word (public/assistant.js:4052); that is the structural concession, and it is what makes the resting tab 73px shorter while the plate is 233px taller.

The lane is a row, not a flex item

The wave block is a sibling of the member strip rather than a member of it (public/core/waves-lane.js:104 and :155). Only with that in place can a lane set of two sit side by side on the wide plate - 637px and 637px - and stack when the pane is 247 wide. A refused lane set draws its own alert and drops the join sentence, because a wave whose lanes cannot be isolated cannot honestly promise a one-commit close.

The density is the reader's

Compact rows re-declares the same tokens one step tighter: space and two fixed heights move, no colour does. The plates in shots 07 and 08 are the same page at the two settings, and the type scale, the contrast and every state role are identical between them.

Everything the document holds is still on the page

78 strings - every title, description, project, tree, branch, assistant, count, wave field, lane and member - looked for in the rendered tab with every fold open, at both widths, before and after. 0 missing in all four passes. The pane's chip count is unchanged at 36; the two buttons it gained are the two new controls.

  • Speed. Nothing here times a render, a repaint or a keystroke. The one interaction that is timed is already in the redesign gate: keyboard focus survives the pane's 4.6s repaint, and it does.
  • Anything outside the tab. The redesign is scoped to #as-initiatives; the panel's other tabs are untouched and unmeasured here.

8Reproduce it

Every number in this report comes from one of these commands. They need no dependencies: the panel has zero, and Playwright is resolved from the global install by tools/browser.mjs.

# the proof the original report never landed: prints nothing
git diff c2692598 ddea5f49 -- docs/reports

# the before column: the old tree, unpacked outside the repo, served by this tree's harness
git archive 86bea38 | tar -x -C <scratch>/before-86bea38

# the probe, run twice. TREE is the product served; HARNESS is the tree whose tools/ are run
env TREE=<tree> HARNESS=<tree> OUT=$SCRATCH/after.json ROUTE_HOME=$SCRATCH/home-a node remeasure-route.mjs
env TREE=<scratch>/before-86bea38 HARNESS=<tree> OUT=$SCRATCH/before.json ROUTE_HOME=$SCRATCH/home-b node remeasure-route.mjs

# the gates, each on its own scratch home so nothing touches the reader's panel
node tools/verify-initiatives-redesign.mjs --home <scratch>/gate --json <scratch>/gate.json
node tools/verify-waves-lane.mjs --home <scratch>/lane
node tools/verify-initiatives-tab.mjs --shots <scratch>/shots
node --test test/waves-lane.test.js test/initiative-fold.test.js

# the captures themselves, when a reader wants a fresh pair rather than the landed one
env ROUTE_ROOT=<tree> ROUTE_OUT=<scratch>/after ROUTE_LABEL=after node docs/assets/initiatives-redesign/route/capture-route.mjs

The probe's page function is byte-for-byte the one in capture-route.mjs; it lives in scratch rather than in the repo because it is a re-read of a landed measurement, not a new one, and a second committed copy of "how big is a row" would be two definitions of the thing under test. If a future run wants a permanent re-check, the honest move is to teach capture-route.mjs a ROUTE_MEASURE_ONLY flag rather than to add a second harness.
