One window per file, for five minutes

Landed 2026-11-12 on branch wtgui/stop-the-panel-and-its-workers-throwing-087364, cut from main. Version 1.89.3. This page records the finding, the change, the tests and the numbers they returned.

Result. The panel now opens a given file once and answers the next open inside five minutes with a REUSE instead of a second spawn. The key is the resolved path from resolveFileTarget, lower-cased on Windows, and the window is five minutes measured from the open (REUSE_WINDOW_MS = 5 * 60_000). A reuse answers ok: true, opened: false, reused: true, ageMs, focus: "none" and the reason in focusWhy. The worker brief gained a SHOWING A PAGE paragraph: declare the page and let the panel's own open route show it, or open one plain tab, never --new-window, never a scratch --user-data-dir, and a scratch browser never outlives the run.

1. Where the duplicate windows actually came from

The finding was verified by grep and holds: --new-window and --user-data-dir appear nowhere in this repository, and fileOpenerLadder builds args: [url] only. The panel's opener was not opening a second window; it was being asked for the same file again by a reader clicking a second time, and by agents that were told to "open the page and prove it" and reached for the browser they knew: msedge.exe --new-window with their own scratch profile. Two paths, two fixes.

It sits in front of the spawn in openFileWith (lib/open-url.js), so every caller of the one opener is covered, not only the two routes.

3. The focus decision

A reuse attempts no focus, deliberately, and says so in focusWhy. On Windows this process cannot raise the tab already showing the file honestly:

  • the reader's registered browser exposes no debug port. A debug port is exactly what a scratch --user-data-dir was for, and giving the panel one means launching a second browser to hold it - the defect itself;
  • relaunching the browser "to bring it forward" adds a tab or a window for the URL, which is the bug wearing a focus's clothes;
  • matching a window by title and calling SetForegroundWindow can raise the reader's own window with the same page, or a console, and it steals focus while the reader is typing - a claim about the screen made from a guess.

A silent no-op would be worse than silence only if it claimed a window, so a reuse never claims one: opened: false, reused: true, focus: "none". The field stays in the answer so a platform that can do it later has somewhere to land without a second return type. A fresh open carries an empty focusWhy: nothing had to decide anything.

4. The instruction path

PAGE_BRIEF is exported beside TERMINAL_BRIEF and TESTING_BRIEF in lib/jobs.js and appended to every run that has a tree (anchorCwd !== false), through the pageText hook. The assistant's own turn has no tree and does not get it. It says four things:

  • a page is proved by a test or a headless capture, never by a browser window thrown at the reader;
  • a page the reader has to look at goes through the panel's own open route (POST /api/open-file, or the anchor a clarify card draws; POST /api/open-url for an http(s) page), so it lands as one tab in a window the reader already has;
  • if the worker opens one itself it is a plain tab: one argv element, no --new-window, never its own --user-data-dir;
  • a scratch-profile browser never outlives the run that started it: close it before you settle, or reuse the one you already have.

The same rule is in docs/runbooks/email-multi.md under ### Showing the reader a page, because a worker reads its project runbook as well as its brief, and docs/runbooks/README.md now tells the next runbook author to carry it.

7. What this does not do

  • It cannot stop an agent from launching a browser - it instructs one not to, and the brief is the only lever the panel has over an agent's own commands. The route-level book mark is the half that holds regardless.
  • It does not collapse a symlink or an 8.3 short name to its target, by choice (see the key table).
  • It does not focus, by choice (see section 3). A reuse is a statement, not a raised window.
