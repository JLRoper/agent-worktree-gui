What the re-export is, for a classic script

public/deliverables.js is not an IIFE: it declares, and the module's one door is window.WMApp.deliverables, built in public/app.js:59-72 from the same bare names. So the re-export is the page's global scope plus the record: a top-level function in public/board/deliver-frame.js is the same window property it was in the entry point, a top-level const the same lexical binding, and public/deliverables.js:250-268 is the record that names all 23 and says where they went. Nothing is declared twice, and app.js still lists every one of the 48 names it listed before. (A module with its own IIFE can alias the moved names inside its own returned object, which is what public/board/paste-chips.js does for the chip cut; a bare-globals entry point has no such object to write into.)
