Defect 1: the running panel predates the filed-tree fix (main already carries it)

Row 66 was filed with no worktree. Under the panel that ran this walk (build 1.80.7) the driver cut one round, then one tree per stage. Each stage tree was handed remoteWrite: "local" because ownStageBranch is true for a stage tree (lib/task-pipeline-drive.js around line 2407 at that build), and the LANDING paragraph for that tree says commit and do not push. Push#1 (ffaabbf3) followed the paragraph, committed 958e9dd, and reported: "this tree is the round's own stage workspace ... the panel's LANDING paragraph for it is the local-only case". Pr#1 (3733218c) then had no ref to point at and recorded a withheld PR in cb26f09.

Main already carries the fix for this shape: 062dbb27 "a landing ladder filed with a work branch runs there, not in a cut round" adds filedTreeOf, which answers a queued row's filed tree for a shared pipeline and refuses a trunk checkout. The panel process was started before that commit, so the walk could not use it; this branch is rebased onto it. The row-67 re-point below is what made the same walk possible on the older build.

The push stage still settled done with nothing on origin. No check in this chain compares the artifact with the remote ref (the driver only evaluates gates that carry verified_by: "pr-comments"), so the row advanced to pr with no branch published.

Defect 2: the Bitbucket payload the host actually sends (fixed on this branch)

Bitbucket Server sends createdDate and approvedAt as epoch-millisecond numbers, and nests a reviewer under user. observeBitbucketPr kept createdDate as a string and read reviewer names from the top level. The wait's clock therefore could not parse any comment, and the reviewer list came back empty. The same real payload through the two modules:

What was repaired by hand, and why

  • Row 67 was filed without a worktree, so the driver cut a fresh round. At build 1.80.7 a queued pipeline row's worktree is refused until the row has started (treeLookup, the note at lib/task-pipeline-drive.js:1149 at that build); main's 062dbb27 changes that for a shared pipeline, but the panel process predates it. The row was parked, re-pointed at the stage-1 tree, and given the real branch start time as startingAt so the older lookup would honour the tree. Its round was cleared; this is the one-tree shape section 2.4 asks for.
  • The stage-1 tree's cut record named the round parent wtgui/...0823a3 as its landing parent, so every pr-kind stage would have been handed the local-only paragraph. The cut record was set to master, which is the branch's real base (bb12884).
  • Job 670ca258 (the abandoned push run in the fresh round) was steered to stop before it wrote anything.
  • Row 66 was parked, then deleted on the reader's instruction. Its branch stage is recorded above.

These are state edits in the panel's own state folder (queue and branch-parents), not panel code changes. They are listed so the walk's provenance is not mistaken for an unmodified driver run.
