Row 547: the route tests' token fixture no longer reads as a credential

agent-worktree-gui. Queue row #547. The tests that drive the panel's HTTP routes passed one fixture value under the key token at 23 lines in seven files, and that key/value pair is the shape a provider-side content filter can read as a credential assignment and redact, which is what breaks a tool call that echoes the file. This page records the one-value change, the grep counts that prove the shape is gone, and the focused test runs that prove nothing else moved.

1. What the row asked for, and where its file list was short

The row names three files and quotes the fixture eleven times. The exercised shape is token: <quoted value>, and the same value is also passed as the x-panel-token header in two of the route harnesses and as a default parameter in two others, so a grep for the assignment alone undercounts the places a worker can echo. A tracked grep for the assignment shape found 19 lines in seven files, and the wider fixture shapes added 4 more lines in three of those files.

Two details of the row's own quote are stale rather than wrong. The excerpt at test/project-turnover.test.js carries a list-shaped turnoverBranches entry; the file today passes the single-key turnoverBranch at test/project-turnover.test.js:355, because the turnover policy grew a second key after that diff was taken. The row's maintenance list stops at 666; the same test's later calls at 670, 681, 687 and 694 carry the shape too.

The four further files are the same class of fixture in the same directory: the route harness's own token, the header the harness sends and the config the route compares it to. None of them is a doc and none carries a test's assertion, so the row's acceptance (no credential-shaped fixture left in a tracked test file) could not be met without them. Their line counts and assertion bodies are unchanged apart from the value.

2. The change, by line number

The edit was made by line number against the bytes on disk, so CRLF survived. Only the quoted value on each named line was replaced; the key, the indentation, the surrounding object and every assert line are byte-identical. The new value is tok-test-alpha, the example the row itself suggests: it reads as a test fixture, not as a credential.

# the shape of each hunk: 23 insertions, 23 deletions, one value per line
-  const config = { ...configOf(dir), token: <retired> };
+  const config = { ...configOf(dir), token: "tok-test-alpha" };
-  const state = { body: {}, token: <retired>, log: [] };
+  const state = { body: {}, token: "tok-test-alpha", log: [] };
-  const h = harness({ body: { project: "alpha", turnoverBranch: "feature/x" }, token: <retired> });
+  const h = harness({ body: { project: "alpha", turnoverBranch: "feature/x" }, token: "tok-test-alpha" });

Nothing compares against the old value, which is why one value is enough: in each harness the request's token and the config's token are the same fixture, so they still match, and the refusal tests still pass a different value deliberately (for example token: "wrong" at test/assistant-digest-route.test.js:69) to get their 403. Replacing the fixture value keeps every one of those meanings.

So the assignment shape went from 19 lines in 7 files to none, the header shape from 2 to none, and the default-parameter shape from 2 to none: 23 fixture lines in all, matching the diff's 23 insertions and 23 deletions. The bare word on its own still appears in documentation prose (33 lines in one design note), which is why the proof is stated on the assignment shapes rather than on the word; documentation is row 573's and is untouched here.
