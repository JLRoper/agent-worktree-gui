What the re-export is, for a classic script

There is no import statement in public/, and this file is an IIFE, so there is no top-level scope to declare into either. The handoff is the page global: public/core/command-summary-git.js:245 publishes root.wtCommandSummaryGit = { countOf, gitParts, gitStep, pathsOf }, and public/core/command-summary.js:407-410 is the record that reads it back, under a comment that says why. In public/index.html the new tag is at line 1310, three lines above the entry point's tag at 1317; the entry point destructures the object the moment it evaluates, so the order is not an optimization, it is the contract.

The one name the page gains. wtCommandSummaryGit did not exist before this cut. A second script is a second global unless the module is folded into the first, and folding is what the cut is for; the card's sentence "the module publishes one object (root.wtCommandSummary)" is kept exactly as far as the published surface goes, and the new global is the classic script's import statement, listed here rather than left for a reader to find.
