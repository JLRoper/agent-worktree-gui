Then: drawn open cards must equal counts.running plus counts.queued, with #402, #404, #411, #438 and #443 all drawn while they run. Two repaint cases ride with it: a queue event that flips a fifth row to running must add its card within one poll, and a page loaded while two rows were queued must show both running after the next poll, with no reload.

Two causes, not one

1. The window counted task ids, not states

queueWindowRows took the twenty highest task ids whatever their state and drew only those (public/queue-cards.js:105 at 895e7282). Ids are handed out in order, so the highest ids are the newest tasks, and any OPEN row older than the twenty newest fell out of the list. The caption above it is built from view.counts, which counts every row in the store, so the two halves of the same pane disagreed: five running above, two below.

2. The view was re-read on a clock, not on a change

renderAssistantQueue asked for a queue read only when its cached view was more than twenty seconds old. The pane is repainted by every board frame, but a repaint inside those twenty seconds drew the old view, so a page open while rows went running kept showing them queued until the clock elapsed. Measured on the pre-fix tree, a row flipped to running through the panel's own route had still not drawn as running after 8,000 ms.

The fix

wherewhat changed
public/queue-cards.js:123queueWindowRows splits the rows: every queued, running and parked row is drawn, always, in the pane's own bucket/order; the twenty-row window applies to the done bucket only.
public/queue-cards.js:921queueMoreHtml now takes the drawn and total counts and leads with showing N of M, so a hidden row is never silent even when what is hidden is only history.
lib/assistant/queue.js:977readQueueFile carries its own stamp (mtime + size) in the result it caches, so the stamp costs no second stat and moves on any writer's write.
lib/assistant.js:1342, :4369, :1262queueView returns that stamp; assistantList returns it per assistant as queueStamp; queueStampOf is the one stat behind both.
public/queue-cards.js:945the pane re-reads when the stamp MOVES and not otherwise: one read per change, none for a board frame that changed nothing, and the twenty-second clock stays as the fallback for a payload that names no stamp.

The stamp is what makes the repaint case work for a writer the panel never hears from: an assistant frame covers this panel's own queue writes, and the stamp covers a queue file written by a script, a worker or another panel, which is read on the page's next poll.
