agent-worktree-gui - row 504 - two page roots, one handler

/docs/ and /reviews/ are two static roots now, and the 43 MB copy is gone

Row 504 was written against a hand-kept copy of the repo's own pages. PR 770 then replaced the hand copy with a request-time one (lib/http/docs-mirror.js), so what the row recorded as a stale copy became an automatic one that still weighed exactly what the pages weigh. What the row asked, and what changed since it was written

The row's diagnosis was right about the cause: lib/http/static.js served exactly one root, public/, so docs/ pages were unreachable while public/docs/ copies answered. Its premise about the copy had moved on by the time it ran. PR 770 landed a mirror that copies on the way to the read (lib/http/docs-mirror.js), so the copy is no longer hand-kept and no longer goes stale - it is simply a second full copy of the pages, rewritten in place, on the same disk.

The row said 42 MB for the docs copy; the brief said the copies now weigh 44M and 13M. Measured on this tree: 40.87 MiB (43M by du) and 11.21 MiB (12M by du). The copy and its source are byte-for-byte the same size, which is the whole point of deleting one of them.

The change

  • Three roots, one handler. PAGE_ROOTS names docs/ at /docs/ and docs/reviews/ at /reviews/; pageRootFor matches a prefix with its separator, so docs-old/x stays a public/ path. Everything else in public/ is served exactly as before.
  • A containment check per root. The resolved file must be the root or sit under it. insideRoot is asked for every request, so /docs/../config.json and /reviews/../architecture-modules.html are 403s rather than reads of a file beside the root or in the other root. No percent-decoding happens on the way in, so an encoded .. is a literal name that 404s instead of a way through.
  • The same MIME table and cache policy. One TYPES lookup from lib/http/respond.js and one policy: the shell is no-store, must-revalidate, an asset the build manifest names is immutable only under the URL that names its bytes, and everything else - including every docs page - is no-store. The versioned branch is now gated on !mount, because the manifest is taken over public/ alone: a docs page cannot become immutable by colliding with a public/ file's name.
  • The route had to be handed the raw path for the check to be reachable at all. server.js parsed every request with new URL(req.url, ...).pathname, and a WHATWG URL resolves .. segments before any handler sees them - so the old containment check only ever met clean paths, and a climb answered 404 from a missing file rather than 403 from the check. The static route now gets the path as it arrived; every other route keeps the parsed one.
  • The copy and the mirror are gone. lib/http/docs-mirror.js (180 lines) and test/docs-mirror.test.js (172 lines) are deleted, nothing imports them, and public/docs and public/reviews are removed from disk. The two .gitignore lines stay, so a hand copy cannot come back as untracked source.
  • Pinned by a new test. test/static-page-roots.test.js (7 cases) serves a real page from each root and compares it byte for byte with its source, refuses six climbing paths with 403, checks a missing page is 404, keeps the shell and an asset at 200, and proves a stale copy left in public/docs cannot shadow the source.

One correction to the row's proof list

The row asks for /docs/architecture.html at the same sha256 as docs/architecture.html. This repo has no page by that name: the docs root has architecture.md (markdown), and the architecture page is docs/reviews/architecture-modules.html, which the reviews root serves. The proof therefore uses three pages that exist - one in the docs root, one under docs/reports/, one in docs/reviews/ - and the reviews page is that architecture page. /docs/architecture.html answers 404, which is the correct answer for a page that is not there.
