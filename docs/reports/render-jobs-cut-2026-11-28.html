2. The boundary the card gets one line wrong

Line 300 is turnBlock's closing brace and line 301 is the blank after it. Line 302 is the comment heading of the stuck-turn chip section, and the heading belongs with the function it introduces at public/render-jobs.js:319. The plan's first range ends at 302 and its second begins at 303, which would put half of one comment block in each file and leave a heading in stream-body.js introducing a function that lives in conversation.js.

So cut 1 takes the code span to the closing brace, 46-300 (the same convention row #538 used for lib/scheduler.js), and cut 2 takes 302-1,282. One consequence is worth saying plainly: the card's one-line summary puts "the stuck chip" under cut 1, but its own range puts the chip in cut 2, and the range decides. The chip and the only function that calls it, conversationHtml's head, are now in the same file.

4. The page surface, before and after

This half of the tree has no import/export: public scripts are classic scripts in a fixed order, and a top-level function is a window property while a top-level let is a script-scope binding every later script reads by bare name. The re-export is therefore the page itself: both new scripts load before app.js, and public/app.js:166's window.WMApp.jobs door still names 17 of the 26 bindings and resolves them to the same globals.
