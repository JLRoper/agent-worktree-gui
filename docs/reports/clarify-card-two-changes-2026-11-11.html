Part A - the caret survives the repaint

What the reader saw

A worker parks on a question and the reader starts typing a sentence into the answer box. The board is live: the row path repaints the card (a move, which keeps the value and drops the focus) and a turn event replaces the node outright (which drops both). The draft map already kept every word, so the box came back full and unfocused, with the caret at 0, in the middle of a sentence.

The fix

captureTyping / restoreTyping in public/app.js already existed for the reply box and the held-reply editor, and returned null for the clarify box, so nothing was ever put back. They now capture the focused .tq-other with its value and its selection range and restore them after the repaint: the value is written only when it differs (a moved card already carries the reader's words, and rewriting them would move the caret), the focus is restored with preventScroll, and the range is re-asserted. The draft map is untouched - forgetQuestionScratch remains the only thing that forgets a draft - and the poll is neither slowed nor suppressed.

Part B - links on a question

What changed

  • lib/clarify-links.js normalizes a links field once, because the envelope is somebody else's: absent is [], a bare string is a target, url/href/path/ file/target are all read, a file:/// URL becomes a path, only http(s) URLs survive (javascript: and data: are dropped, not thrown), and the cap applies after the refusals.
  • public/app.js questionLinks reserves a block between the question text and the choices: one anchor per link, the label as its text and the target under it. A URL rides data-open-url; a file rides data-open-file. No links, no section - the plain-text card is exactly what it was.
  • linkifyCardText in public/core/dom-format.js links a bare URL or path still sitting in the question text, so an old-style call yields a clickable card. A drive letter is a path and not a scheme, a sentence's full stop stays in the sentence, and and/or or 24/7 is left alone.
  • POST /api/open-file walks the landed 1.81.9 ladder - HKCU UrlAssociations default browser, then rundll32 url.dll,FileProtocolHandler, then explorer.exe - never a hard-coded Chrome, and answers with the step that started. A relative link is resolved against each open project; a file outside every project is refused 403, a missing one 404.
  • the worker brief (CLARIFY_LINKS_BRIEF) and the per-turn instruction (lib/clarify.js) now tell a worker the field exists, so a new card arrives with it.
