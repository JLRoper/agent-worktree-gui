The queue card: every agent on its own line

1.184.0 - the facts line stops laying agent rows side by side. Measured boxes before and after, and the gate that keeps them.

A task carried by two threads drew its two agent rows side by side on one line, and the facts line's 8 px column gap between them read as the separator between two agents. The reader photographed it on #371, an EXITED thread followed by a RUNNING one. Each agent now takes a line of its own, on the facts block's left edge, and the project / PR meta line keeps its own row under them. A card with one agent measures exactly as it did.

What was wrong

div.as-task-facts is a wrapping flex row with a 2px 8px gap public/style.css:7006, and the full card joined its agent markup straight into it: 

list.map((th) => queueAgentHtml(id, t, th, jobs)).join("")   // public/queue-cards.js:775, before this cut

So every div.as-task-agent was a flex child of the facts line. At a pane wide enough to hold both, the layout engine put them in the same row - which is not a wrap, it is the row rule - and nothing in the markup said "these are two agents, one per line". A column container existed (.as-task-agents, public/style.css:6922) but the queue card never used it, and it carries a 19 px left margin that belongs to the Initiatives pane's listing, so reusing it would have indented the queue's own rows.

The fix

The agent rows are one block now, a child of the facts line, and the block is a column public/queue-cards.js:781, public/style.css:7016-7021: 

<div class="as-task-facts">
  <div class="as-task-agent-stack">   <!-- column, no indent, full width from two rows up -->
    <div class="as-task-agent">... thread one, its run id, its pill ...</div>
    <div class="as-task-agent">... thread two, its run id, its pill ...</div>
  </div>
  <span class="as-task-meta">project agent-worktree-gui · PR NO COMMITS</span>
  <span class="as-task-pipeline">...</span>
</div>
  • One wrapper, .as-task-agent-stack, with display:flex; flex-direction:column; gap:2px and margin:0: no horizontal indent of its own, because the facts line already carries the 18 px.
  • From two agent rows up the block takes the whole line (:has(> .as-task-agent + .as-task-agent)), which is what pushes the meta line onto its own row after them. A one-agent card takes the same column and has nothing to stack with, so its geometry is unchanged.
  • The row is full width now, so the pill's own margin-left:auto would park an EXITED chip at the far edge of a 1100 px card. Scoped back to 0 inside the block: the chip stays beside its thread and its run id. Measured after the first pass: the chip sat 700 px from its thread before this rule, 4 px after it.
  • The compact card is untouched: that mode builds its own single-thread line and never goes through the stack public/queue-cards.js:730-734, public/core/task-card.css:45.

The gate

tools/verify-queue-agents.mjs is a LIVE GATE. It slices the renderer out of the shipped public/queue-cards.js (the same slice test/assistant-queue-ui.test.js uses), renders four fixture cards - two threads, three threads, one thread, and a compact one - into a page carrying the four stylesheets public/index.html loads, in that order, and measures the boxes in Chromium. Nothing boots: no panel, no queue file, no port.
