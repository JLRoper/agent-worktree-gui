The driver at origin/main refused it: a queued pipeline row with no tree of its own answered needed, so the sweep asked for a round's parent tree and no stage could start. filedTreeOf in lib/task-pipeline-drive.js reads that one case, and only under four facts: the row is queued and has not started; the pipeline is not per-stage, because a per-stage round still cuts one child per stage; the directory exists; and the panel's own git read answers a branch for it that is not a trunk. A filed path on main, which is the checkout from row 50, is still refused and still cuts the round's parent tree. The stage brief also names the branch now: it read a field the lookup never sets, so every brief had said (unknown) even when the row carried the branch.

The change is 04e3a150 on this tree's branch: lib/task-pipeline-drive.js, test/task-pipeline-drive.test.js, and the paragraph in docs/task-pipeline.md that said a row's worktree never names a tree before the cut.

6. What this does not prove

The row ran on a second panel instance, not the reader's. The fix under review is what makes the row walk, and the reader's panel runs origin/main's driver. So a panel was booted from this tree on port 7332 with a copied store (one project, one assistant, an empty queue, its own state directory) and the row was filed there through POST /api/assistant/queue. The reader's panel was not restarted and its board is unchanged. The evidence is that panel's queue.json and jobs.json plus the real GitHub effects above.
The version gate did not run. The scratch tree was cut by hand with git worktree add, so it carries no core.hooksPath and no pre-commit version check. The version stage's own node tools/version.mjs calls did run and chose 1.80.9 over 1.80.8.
The gates cannot refuse. All six gates are declared with no decision, so the row paused at none; a ladder with a decision gate would answer pause and wait for a reader, which no sweep can give itself.
This tree's version is unchanged. The scratch landing took main to 1.80.9 and created the tag v1.80.9 in the shared repo; this tree still carries 1.80.8 and no bump. Its landing is the reader's call.
