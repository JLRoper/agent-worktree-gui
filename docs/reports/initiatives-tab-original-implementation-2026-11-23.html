Forensics - the Initiatives tab's rewrite

What happened to the original implementation

The code was never lost. The page that documented it was, and it was destroyed by two rules that are both still in force today: an untracked file in a worktree, and a shared info/exclude that hides every docs/reports/*.html from git status.

Written 2026-11-23 Measured at origin/main cf72e299 (1.157.9) plus this branch Method git refs and tree hashes, the landed PRs, one reproduced probe Verdict code intact, report destroyed and rebuilt

01The answer

Four different things can be called "the original implementation of the Initiatives tab rewrite". Three of them are intact, one is gone, and the gone one is not code.

  1. The tab itself, created in 1.119.0 (PR 791, merged 2026-11-19T16:19Z) as "a tab beside Role, and an Initiative column on the chart". All twenty files it added are still in the tree: lib/chart-columns.js, public/charts.js, public/chart.css, public/render-projects.js. The chart's Initiative column still draws (public/charts.js names the initiative four times).
  2. The redesign's first implementation, 1.144.0 (PR 818, merged 2026-11-21T07:50Z): 8 files, +1,942/-95, the rubric at 4 of 16 before and 16 of 16 after. It was not replaced by a rival branch; The Route (PR 852) evolved it in place. Its two-column grid is still the grid the wide card uses, its empty states are still drawn, and its gate tool is still the gate. Its 4px spacing scale and four-step type scale are the part that did not survive.
  3. The Route's first cut, 0773a88a on wtgui/build-the-reader-s-chosen-initiatives-b58037: landed byte for byte as 01c22b3f (identical tree 81d41afd), then amended by the three after-review commits in 1.157.6. Nothing about it was dropped in the rebase, and its branch is still on origin.
  4. The implementation report, the page that measured the rewrite: destroyed. It was written as an untracked file in a worktree that was then deleted, and git status never showed it because .git/info/exclude line 13 ignores docs/reports/*.html in every worktree. PR 854 rebuilt it and force-added it, and its own opening sentence says so: "This page is a rebuild. The first one was lost."

The short answer

If "the original implementation" means the code, nothing happened to it: it landed, and each later round changed it in place, so every version is reachable by hash and most of it is still in the tree. If it means the page that recorded the implementation, it was destroyed by the untracked-file-plus-exclude pair, and what exists now is a rebuild that re-measured rather than recovered.

03Nine commits that look unlanded, and the twins that prove they are not

A commit that is not an ancestor of main reads like lost work. Nine commits touching the tab's own module and its routes are in that state, and every one of them has a twin on main with an identical tree, because each landing branch was rebased onto main rather than merged.

04The one thing that was lost, and the two rules that lost it

PR 854 explains it in its own body, and both causes are still in force today.

The page was written by row 205's worker as an untracked file in its worktree. Untracked and then a deleted worktree means gone: there is no object to recover, because no object was ever created. The second half of the cause is the one that made the loss silent, and it is worth quoting exactly:

PR 854, why there is a rebuild

"The original page was written by row 205's worker as an untracked file in its worktree, so it died with the tree: git diff c2692598 ddea5f49 -- docs/reports on the landed commits prints nothing. The second half of the cause is the one that made the loss silent: this clone's .git/info/exclude carries docs/reports/*.html under "Generated reports are local artefacts", and info/exclude is shared by every worktree, so git status never showed the file at all."

I re-ran the check the quote makes, on this tree: git diff --stat c2692598 ddea5f49 -- docs/reports prints zero lines, so the Route's landed commits carried no report at all. And the exclude rule is still there, at .git/info/exclude lines 12 and 13:

12: # Generated reports are local artefacts
13: docs/reports/*.html

Which meant the trap was armed. Writing an untracked report into docs/reports/ and asking git status about it produces no output at all, and the ignore is inherited by every worktree because info/exclude lives in the shared git directory:

$ : > docs/reports/zz-probe.html
$ git status --short docs/reports/zz-probe.html
$ git check-ignore -v --no-index docs/reports/zz-probe.html
<repo>/.git/info/exclude:13:docs/reports/*.html	docs/reports/zz-probe.html

The first command produced a file, the second printed nothing, the third names the rule. A worker that checks its own work with git status sees a clean tree while the only copy of a page sits untracked on disk. PR 854's own sentence for it: every .html report on main got there with git add -f, and this page did too.

This page had to be added the same way. It is the one detail of this report that is also a demonstration of its own subject.

What the rebuild did and did not recover

The rebuilt page re-measured the implementation at 1.157.4 rather than recovering the lost numbers: its "before" column is a git archive of 86bea38 (1.157.1) served by the same harness, which is the right call and a different thing from the original's own run. So: the code's history is intact, the original page's own measurements are gone, and what a reader can open today is a re-measurement of the same question.

05What survives of the original implementation, and what does not

Survives, unchanged in intent

  • The wide card's two-column grid. At 1.144.0 it is public/style.css:4825, a @container (min-width: 1000px) with areas head, desc, chips, side, assist, hist. Today it is public/style.css:5658, the same container query and the same areas, restyled in round B's tokens and with one row added: "waves waves". The Route built on the grid, it did not replace it.
  • The empty states. .init-empty is still styled four times in public/style.css and drawn twice in public/assistant.js.
  • The gate and its harness. tools/verify-initiatives-redesign.mjs, the fixture, the measure tool and the 1.144.0 baseline are all still in the tree, and the gate answered 11/11 claims and 16/16 docked when it was written; it now answers 11/11 claims, 18/18 docked and 17/18 wide, because the Route added claims to it.
  • The 1.144.0 page itself, docs/reports/initiatives-redesign.html ("Initiatives tab: measured before, redesigned after"), still tracked on main and still openable.
  • The store and the routes created in 1.119.0: lib/initiatives.js and routes/initiatives.js are the same two files the tab reads and writes through now.

Does not survive

  • The 4px spacing scale and the four-step type scale. None of their token names are left: --init-space and --space-1 each answer 0 in public/style.css, where the Route's --tab-s1 to --tab-s6 now carry 26 uses between them.
  • The column widths. 1.144.0 asked for minmax(0, 72ch) minmax(320px, 640px); today the grid is minmax(0, 66ch) minmax(320px, 1fr), so the side column can take the width the pane has instead of stopping at 640px.
  • The original page's measurements, as above: replaced by a re-measurement, not recovered.

09The trap, and the test that closes it

The reader's decision on this page was to stop the silence rather than remember it. The branch now carries a check that makes a report page under docs/reports/ impossible to leave behind unnoticed.

Two files: tools/reports-tracked.mjs, which compares every .html on disk under the report folder against git ls-files docs/reports, and test/reports-are-tracked.test.js, which fails with the list of pages and the fix. The comparison is against the INDEX, not git status, because that is the difference the whole page is about: an ignored file is invisible to status and visible in the index.

The checkWhat it answers
this tree3/3 green - every page on disk under docs/reports is in the index (33 of them at the time of writing, and the test refuses to pass on a listing that finds fewer than 30)
a probe page, written and not addedred - git status --short printed only the two new source files, and the test named docs/reports/zz-probe-lost-page.html and printed Fix: git add -f <page> to keep it, or delete it; the probe was then deleted and the test went back to 3/3
a fixture repo carrying the real rulered then green - # Generated reports are local artefacts plus docs/reports/*.html in its own .git/info/exclude: status silent, the check names the page, git add -f clears it
a page one folder downfound - docs/reports/round/deep/page.html, because reports keep their evidence beside them

The ignore rule itself stays: a generated page is still untracked by default, and a hand-written report is still committed with git add -f. What changed is that the default is now loud. Its comment in .git/info/exclude points at the test, for the next reader who wonders why the line is there.

What the check does not do: it only speaks when the suite runs, so a worker that never runs the tests still gets the old silence, and it only walks docs/reports - a page written anywhere else was never covered by the rule. Both are honest limits of a test, and both are better than a rule that hides the one artefact a round exists to produce.
