What app.js still owns

17,684 lines and 672 declarations is the state store, the event wiring, boot, the polling loop, and the surfaces that were in no cut: the board's own DOM scaffolding, the host bar, the queue's non-card parts, the charts' and deliverables' call sites, and the 54 paint* functions. The first page's estimate was that the eight cuts would leave app.js near 8,000 lines. It left 17,684, because the cuts moved coherent slices and the file kept the central wiring, which is the half of that estimate worth correcting here: the seams that were cut were real, and they were not the ones holding most of the file.

The remaining lane, in the order I would still cut it:

  1. The four route prefixes step 8 named and did not cut: state, jobs, pipelines, settings. The table is already there, so each is one module plus one row.
  2. public/app.js's board scaffolding: the element builders and the panel wiring that every remaining surface still shares. It is the dom.js cut repeated on what dom.js left behind.
  3. public/style.css at 4,749 lines: one sheet for every surface, and the only file in the top five that has never been cut.

On lanes

The first page's definition still holds: a lane is a file two rows both need. What changed is the size of the file at the head of it. A row that touches the board now edits a 1,440-line project renderer or a 911-line job renderer instead of a 22,157-line page, and the seven files the next five steps cut prove the re-export pattern holds at every size. The remaining single-lane file is public/app.js at 17,684, and the four uncut route prefixes keep server.js a second one for anything that adds an endpoint.
