Container cleanup as a panel behaviour

agent-worktree-gui, 2026-11-23, assistant-3, row #269. Proved on Docker 29.5.2 (Docker Desktop) against a real daemon.

Container cleanup is now the panel's, not the worker's habit. A worker is told the two labels and --rm; a settle stops and removes every container carrying the ending tree's wag.worktree label; a new panel action does the same on demand for a named tree; and a queue row cannot be closed while its tree still runs a labelled container, unless the close reason names it and says why it is kept. Seven checks ran against the daemon and all seven passed: PASS all 7 steps.

The convention, and why it is labels

The panel already has a docker convention and this does not replace it: lib/merge-prompt.js:222 asks a merge run for docker compose -p wtgui-merge-<stamp> and tears that project down with docker compose down (lib/merge-prompt.js:230). A name is for the reader. What the panel can read BACK is a label, so the labels are what the teardown keys on, and a container is findable whatever it was named and whoever created it:

labelvalueused for
wag.worktreethe tree's absolute path, forward slashes, no trailing slashthe teardown key, matched exactly
wag.rowthe queue row's id, digits onlythe refusal sentence, so a person sees whose container it is

The tree match uses the panel's one tree spelling (lib/push-guard.js:59 normTree), which folds backslashes, a trailing slash and the MSYS /c/x form onto one key, so a label written from git bash and a label written from the panel's own path are the same tree.

The paragraph a worker now receives

Built by containerBriefFor (lib/container-teardown.js:199) and appended to the tree run's brief at lib/jobs.js:4145, with THIS run's tree written into the label value:

CONTAINERS - a container you start outlives your turn, so it has to be findable without you: every container you start carries the panel's two labels, and every `docker run` starts it with `--rm`.
  docker run -d --rm --label wag.worktree=<this run's tree> --label wag.row=<the queue row this brief names, digits only> ...
`wag.worktree` is the teardown key: this run's tree, absolute, forward slashes, no trailing slash. `wag.row` is the queue row you are working for (digits; leave it off a run with no row). A `docker compose` service carries the same two labels in its `labels:` block - the panel reads labels, not names or compose project names, so a name alone is invisible to it.
The panel stops and removes every container carrying your tree's label when this run settles, and it refuses to close your row while one is still running unless the close reason names it and says why it is kept. `--rm` is the habit; the label is the contract.

What it does not do

  • An unlabelled container is invisible. That is the honest limit of a label: the panel can only stop what it can find, which is why the brief paragraph is half the feature. The settle's log line says what it did, not what it missed.
  • The close gate fails open. The queue write is a synchronous door, so the gate reads the daemon synchronously with a 4 s ceiling; a docker that cannot answer is a log line, never a row a reader cannot close. A failing daemon is remembered for a minute so a settle loop does not spawn docker per turn.
  • The merge flow's compose teardown is unchanged. docker compose -p wtgui-merge-<stamp> down is still the merge run's own cleanup; the labels are the net for what a worker forgets, and adding them to a compose service is the worker's step the brief now asks for.
  • No browser control was added. The action is the route the panel exposes (and the refusal sentence points at it); the board's own chip for it is a later UI pass, not a second convention.

How to run it

node tools/verify-container-teardown.mjs
WTGUI_TEST_IMAGE=<an image this daemon has> node tools/verify-container-teardown.mjs
node --test --test-concurrency=1 test/container-teardown.test.js test/container-brief.test.js

Both the test's daemon block and the verify tool SKIP with a named reason on a machine with no Docker daemon or no image, and neither pulls an image: a test may not reach the network on a reader's machine. The default image is node:24-bookworm-slim; WTGUI_TEST_IMAGE overrides it.
