3. Load order, and why none of this is an ES module

The page is classic scripts and stays classic scripts. public/index.html:1618 loads /board/approvals.js, then replies, spawn, worktrees, merge, anchor and columns in cut order, public/index.html:1673 loads /settings-window.js, and public/index.html:1674 loads /app.js last. Every module only declares at top level, so the order costs nothing and nothing waits on boot; app.js, which runs first in page time, finds them as page-wide bindings. The window.WMApp objects are the one door for a later module that would rather reach a name through an object than a page global.
