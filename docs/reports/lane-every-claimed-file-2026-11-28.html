1. What row #483 asked for

The row's own words, abridged to the four requirements:

(1) laneRefusal and the lane-head computation must intersect EVERY file a row claims, not just the head,
    and name the shared file in the refusal;
(2) the existing allow-overlap door is the escape ... so generalise it rather than adding a second mute;
(3) a test that cuts two rows whose overlap is a NON-head file and proves the second is refused with
    that file named;
(4) keep the head-file lane exactly as strict as it is, the change is additive.
Do not delete the 14 kept collision notices as part of this row: they are the evidence.

2. What the code did before this branch

The cut's predicate was already the whole-set one. liveRowHolders (lib/spawn-check.js:178) intersects this row's entire files array with each candidate holder's entire files array through intersectingFiles (lib/queue-files.js:28), and laneRefusal (lib/spawn-check.js:249) names every shared file it finds. That is why the forced overlap below was refused even on the base: a check that matched one file per row was never in the cut.

The head-file limitation lived in the lane's ORDER, and that order is what the pane and the digest print. laneInfo gave each row ONE lane name - the first file it shared with its lowest-id peer - and then grouped rows BY THAT NAME. Three consequences, all measured on this tree against the base:

  • a row that shared file x with a live peer but whose lane was named y (from a different peer) sat OUTSIDE the lane and was told to wait for nobody;
  • a row with a lower id than the live peer was printed as (head) - "the one that goes first" - while the live row it shared a file with was already running;
  • the live row itself printed no order note at all, so nothing on the line said it had overtaken the row the lane told to go first.

The base, on three rows: #1 queued on public/app.js, #2 RUNNING on public/app.js, public/console.css, #3 queued on public/console.css. #1 and #3 share nothing, so only a lane built from whole filesets holds all three.

6. What stays exactly as strict as it was

  • the head-file lane: two rows that share their head file produce the same lane, the same head and the same waiting on #N (lane X) sentence as before. test/queue-holds.test.js:322 and :341 are unchanged and green.
  • the allow-overlap door: one exception covers one holder and one file (lib/assistant.js:2539; test/spawn-lane.test.js:256). An exception on one of two shared files still leaves the other as a refusal, which is the point of a recorded decision rather than a mute.
  • the per-tree guard: heldTreeRefusal and jobs.create's tree checks are untouched. The lane is a second check beside it, never a replacement.
  • a parked row: still takes no part in a lane - it is waiting for a person, not for a run.
  • nothing is started: the lane is a read. The digest, the pane and the chat list render what the store derived; no state, id, thread or attempt is touched (test/queue-holds.test.js:387).

8. What is still open

  • The lane reads ONE assistant's queue. taskLaneCheck is handed out.tasks - the queue of the assistant carrying the SPAWN - so a row in assistant-1 and a row in assistant-3 that claim the same file are two lanes, not one. That is outside row 483's words ("every file a row claims"), but it is the next hole of the same shape now that the fileset half is closed.
  • The claims are a promise, not a measurement. The lane knows what a row CLAIMS; a worker that edits a file it did not claim is still found by the collision pass after the fact. Covering every claimed file does not make the claim complete.
  • The gate above needs its parked-line expectations re-pinned (section 7) before it can be trusted as a green gate again.
