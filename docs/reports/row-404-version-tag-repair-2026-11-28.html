What the tools now refuse, in one rule with two named exceptions

A version tag is a repository-wide claim, and a reader of main can only follow a commit main took. So a tag whose commit is not an ancestor of main is not an anchor, whatever package.json at that commit says.

  • The gate (npm run verify:version-tags) reports off-main when a version tag main does not carry is still held by a branch, naming the tag, its commit and every branch that holds it. tools/verify-version-tags.mjs:121-137, tools/release-history.mjs:257-276
  • A wrong-commit finding now says the same about a tag the walk does join: the message ends with the commit's ancestry and the branch holding it. tools/verify-version-tags.mjs:162-167
  • The renderer (npm run changelog) refuses before writing anything when a section it is about to write names a release whose tag's commit main never carried. tools/changelog.mjs:404-431, 444-452
  • Exception 1, the branch's own bump. A branch's newest number, tagged on the commit that declared it, is still held rather than refused - that is the pre-landing anchor version.mjs apply writes, and the landing moves it onto the commit main carries. tools/release-history.mjs:262-272
  • Exception 2, the fossil. A tag no branch holds at all cannot be landed from, so it is reported as a note rather than a refusal no reader can act on. The gate prints 47 of them as notes on this history. tools/release-history.mjs:198-214, tools/verify-version-tags.mjs:141-157

The renderer's refusal is scoped to the sections it writes, and that scope is what makes it usable: a kept section is the file's business and the gate's, and another branch's unlanded bump is not a claim a render of main makes. Without the scope, a render of main in this live repository refuses on a neighbour's draft tag. tools/changelog.mjs:16-28
